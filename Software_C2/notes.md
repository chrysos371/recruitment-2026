# 学习过程与踩坑记录 — YOLO 目标检测

## 学习过程

### 阶段一：理解 YOLO 目标检测

之前做 C1（OpenCV 人脸模糊）用的是 Haar Cascade 传统方法——速度快但只能检测特定类别。YOLO (You Only Look Once) 是深度学习时代的检测范式：

| 对比 | Haar Cascade | YOLOv8 |
|------|:-----------:|:------:|
| 方法 | 传统特征 + 级联分类器 | CNN 端到端 |
| 类别 | 只能检测训练过的类别 | 可训练任意类别 |
| 精度 | 中等 | 高 |
| GPU 需求 | 不需要 | 推荐 |

YOLO 的核心思想：把图像分成 S×S 网格，每个格子预测 B 个边界框 + 类别概率。单次前向传播完成检测，不需要滑窗或区域提议。

### 阶段二：数据标注策略

68 张图片手动标注的工作量：假设每张图 8 个目标，每个框 15 秒 → 68×8×15 = 2.3 小时。

**预标注优化**：用 YOLOv8n（COCO 预训练）自动检测 person 和 motorcycle，生成 530 个初始框。人工只需：
1. 判断 person 是社区/非社区（秒级判断）
2. 删改误检和漏检

实际人工时间从 2.3 小时降到约 40 分钟。

### 阶段三：训练与调参

基于 ultralytics 框架的 YOLOv8 训练流程：
- 加载预训练权重 → 冻结 backbone 前几层 → 微调 head
- 强数据增强弥补 68 张图的小样本问题
- 监控 mAP@50 和 mAP@50-95 曲线判断收敛

## 踩坑记录

### 坑 1：Python 3.14 + ultralytics 兼容性

**现象**：`pip install ultralytics` 后 import 报错，部分依赖不兼容 Python 3.14。

**解决**：ultralytics 团队跟进快，最新版已支持 3.14。`pip install --upgrade ultralytics` 即可。

### 坑 2：CPU 训练速度

**现象**：YOLOv8n 在 CPU 上一个 epoch 约 30-40 秒（68 张图），100 epochs 需要约 1 小时。

**应对**：
- 先用 `epochs=50` 快速验证管线是否跑通
- 确认无误后再跑完整 100 epochs
- 如果换用 AutoDL（RTX 3090），每个 epoch < 1 秒

### 坑 3：预标注的 person 类别歧义

**背景**：COCO 预训练模型只知道 "person"，无法区分"社区人员"和"非社区人员"。所有 person 检测框默认标为 class 0 (community_person)。

**影响**：如果不做人工修正直接训练，模型会把所有人都预测为社区人员，非社区人员的召回率为 0。

**解决**：必须人工过一遍——社区/非社区的判断依据是参考图（红框 = 非社区）。

### 坑 4：小数据集训练注意事项

**数据增强必须开足**：68 张图对于深度学习来说非常小。YOLOv8 默认增强不够，需手动调大：
```python
hsv_h=0.015, hsv_s=0.7, hsv_v=0.4,
degrees=10.0, translate=0.1, scale=0.5,
mosaic=0.5, fliplr=0.5
```

**不要训练太久**：小数据容易过拟合。监控 mAP 曲线，验证集指标不再上升就早停。

**预训练权重必须用**：`yolov8n.pt` 在 COCO 上训练过，backbone 已学会通用特征。不加载预训练的话 68 张图根本训练不出来。

### 坑 5：预标注漏标——人工补不回来

**现象**：预标注用 YOLOv8n COCO 检出 530 框，但实际图像里还有很多目标**根本没被框出来**（遮挡、小目标、密集人群、特殊姿态都被漏了）。

**认识**：人工修正主要以「删误检 + 改类别」为主（删了 205 个误检框），但**逐图系统性补全所有漏检目标几乎不可能**——人眼一张张找漏标的工作量远超删误检。所以最终数据集的召回存在固有缺口。

**影响**：模型 mAP 反映的是「在这个有召回缺口的数据集上」的表现，实际部署时召回率会进一步下降。这属于「预标注 + 单轮人工修正」方案的固有限制，已在 README「数据标注的偏差与局限性」一节如实说明。
