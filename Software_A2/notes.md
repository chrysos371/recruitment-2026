# 学习过程与踩坑记录 — Shape 图形类体系

## 学习过程

### 阶段一：理解多态的本质

A1 练了封装和运算符重载，但都是编译期确定的行为。A2 的核心是**运行时多态**——同一个接口调用，根据实际对象类型执行不同代码。

关键概念回顾：

| 概念 | 说明 |
|------|------|
| **虚函数** (`virtual`) | 允许派生类覆盖，通过基类指针调用时走派生类实现 |
| **纯虚函数** (`= 0`) | 基类不提供实现，派生类必须覆盖，使基类成为抽象类 |
| **虚析构函数** | `virtual ~Shape() = default`——防止 `delete` 基类指针时派生类析构被跳过 |
| **vtable** | 编译期为每个含虚函数的类生成的函数指针表，运行时通过查表实现动态分发 |
| **模板方法模式** | 基类定义算法骨架（非虚），具体步骤交给派生类实现（虚函数） |

### 阶段二：类层次设计

选择了最常见的几何图形体系：

```
Shape (抽象基类)
├── Circle    — πr² / 2πr
├── Rectangle — w×h / 2(w+h)
└── Triangle  — 海伦公式 / a+b+c
```

**为什么选这三个：**
- Circle 最简单——一个参数，面积和周长都直接套公式
- Rectangle 也很简单，但用了两个参数，体现构造函数的参数差异
- Triangle 最有挑战——海伦公式 + 三角不等式校验，能体现参数校验的独立性

### 阶段三：多态演示设计

在 main.cpp 中安排了 7 组演示：

1. **基本功能验证**：每个类单独创建，验证面积周长数值正确
2. **基类指针动态绑定**：`vector<unique_ptr<Shape>>` + 循环调用虚函数
3. **模板方法模式**：基类非虚 `print_info()` 内部调用虚函数
4. **基类引用多态**：`const Shape&` 参数同样触发动态绑定
5. **三角形专项**：等边三角形 + 非法三角形异常
6. **实际应用**：按面积排序——不关心具体类型，只依赖 `area()` 接口
7. **编译期约束**：说明 `Shape s;` 会直接编译报错

## 踩坑记录

### 坑 1：忘记 `#include <algorithm>`

**现象**：
```
error C2039: "sort": 不是 "std" 的成员
```

**原因**：`std::sort` 定义在 `<algorithm>` 中，只包含了 `<vector>` 和 `<memory>`。

**解决**：加 `#include <algorithm>`。这个坑在 Python 里不存在（`sorted()` 是内置函数），但在 C++ 里每个标准库组件都严格依赖对应的头文件。MSVC 有时会"隐式包含"一些头文件（比如 `<iostream>` 可能会间接引入 `<string>` 的部分），但 `std::sort` 不会被隐式引入。

### 坑 2：`std::numbers::pi` 的 C++20 依赖

A1 中没有用到数学常量，A2 计算圆形面积时需要 π。

**选择**：`std::numbers::pi`（C++20 `<numbers>` 头文件），精度足够（`double`），比 `#define PI 3.14159265358979323846` 更优雅。

**编译时注意**：必须 `/std:c++20`，否则 MSVC 找不到 `<numbers>` 头文件。

### 坑 3：虚析构函数的必要性（设计经验）

一开始想省略虚析构函数——毕竟 Shape 没有动态分配的资源。但考虑以下场景：

```cpp
std::vector<std::unique_ptr<Shape>> shapes;
// unique_ptr 析构时调用 delete 基类指针
// 如果没有 virtual ~Shape()，派生类析构函数不会被调用
```

虽然本题的派生类没有需要释放的资源，但**写上虚析构是良好习惯**——以后如果有人给 Circle 加了动态分配的成员却不加虚析构，就会出内存泄漏。默认 `= default` 即可，零成本。

### 坑 4：三角不等式的方向

**错误写法**（曾考虑过）：
```cpp
if (a + b < c || a + c < b || b + c < a)  // 错！
```

**正确写法**：
```cpp
if (a + b <= c || a + c <= b || b + c <= a)  // 对！
```

三角形要求**严格大于**——`a + b > c`。所以不合法条件是 `a + b <= c`（包含等于的情况，此时三点共线退化为线段，面积为零，不能构成真正的三角形）。
