# 学习过程与踩坑记录 — Markdown

## 学习过程

### 阶段一：了解 Markdown 是什么

Markdown 是一种**轻量级标记语言**，由 John Gruber 于 2004 年创建。核心理念是用纯文本语法实现结构化排版，最终能被渲染为 HTML。与 Word 等富文本编辑器相比，Markdown 的优势在于：

- **纯文本**：任何编辑器都能打开，版本控制友好（Git diff 清晰可读）
- **语法简洁**：学习成本极低，15 分钟即可上手
- **跨平台**：GitHub、Notion、飞书等主流平台原生支持
- **可嵌入代码**：代码块 + 语法高亮是技术写作的刚需

主要学习资源：[Markdown 官方教程](https://markdown.com.cn/basic-syntax/)

### 阶段二：掌握核心语法

核心语法可归纳为以下 7 类：

| 类别 | 语法 | 应用场景 |
|------|------|----------|
| 标题 | `# ## ###` | 文档层级结构 |
| 强调 | `**粗体** *斜体*` | 突出重点 |
| 列表 | `- 1.` | 步骤说明、要点罗列 |
| 链接/图片 | `[]()` `![]()` | 引用外部资源、展示截图 |
| 代码 | `` ` `` ` ``` ` | 技术文档核心 |
| 表格 | `\|--\|` | 对比分析、参数说明 |
| 引用 | `>` | 引用外部资料 |

### 阶段三：实践应用

在本次招新考核中，所有 14 道题的文档均使用 Markdown 编写。通过大量实践，逐渐形成了以下习惯：

- 代码块始终注明语言标识（如 `python`、`cpp`、`bash`），确保语法高亮正常
- 表格使用对齐符号（`:--`、`--:`）提升可读性
- 图片统一放在 `screenshots/` 子目录，使用相对路径引用
- 标题层级不超过三级，保持文档扁平可导航

## 踩坑记录

### 坑 1：GitHub 不支持 LaTeX 数学公式渲染

**现象**：在 GitHub 上查看 `.md` 文件时，用 `$...$` 或 `$$...$$` 包裹的 LaTeX 公式显示为纯文本。

**原因**：GitHub 的 Markdown 渲染器（CommonMark）出于安全考虑，默认不解析 LaTeX 数学公式。

**解决方案**：
1. 使用 VS Code 的 Markdown Preview Enhanced 插件 —— 本地预览完美支持 LaTeX
2. 如需在 GitHub 上展示，使用 [CodeCogs](https://latex.codecogs.com/) 在线编辑器生成 PNG 公式图片
3. 或在 Typora 中编辑并导出为 PDF 提交

### 坑 2：代码块中的反引号嵌套

**现象**：想在 Markdown 文档中展示如何写 Markdown 代码块，结果渲染出错。

**原因**：嵌套代码块时，内层的三个反引号会被解析为外层代码块的结束符。

**解决方案**：使用**四个反引号**或更多来包裹外层代码块：

```markdown
````markdown
```python
print("Hello")
```
````
```

### 坑 3：表格中 `|` 与特殊字符冲突

**现象**：表格单元格内包含 `|` 字符（如管道操作符）时，表格被错误切分。

**原因**：`|` 是 Markdown 表格的列分隔符，单元格内容中的 `|` 会被误解。

**解决方案**：使用 `\|` 转义，或用 HTML 实体 `&#124;` 替代。

### 坑 4：Windows 与 Linux 换行符差异

**现象**：Git Bash 中编辑的 `.md` 文件在 Linux 上查看时多了 `^M` 字符。

**原因**：Windows 使用 `\r\n`（CRLF），Linux 使用 `\n`（LF）。

**解决方案**：在 VS Code 右下角将换行符设为 LF，或配置 `.gitattributes`：
```
*.md text eol=lf
```
