# 学习过程与踩坑记录 — 红绿灯检测

## 学习过程

### 阶段一：理解传统 CV 检测范式

C1 用了 Haar Cascade（传统但只针对人脸），C2 用了 YOLO（深度学习端到端）。C3 要求回到最基础的传统 CV pipeline：

```
预处理 → 颜色分割 → 形态学 → 轮廓过滤 → 决策
```

对照题目要求的五个干扰场景，逐一设计应对策略：

| 干扰 | 原因 | 对策 |
|------|------|------|
| 阳光反光 | 高亮度低饱和度 | HSV S 阈值提高，白色反光 S 低 |
| 夜晚灯光 | 整体暗，V 低 | 自适应 V 阈值 |
| 红色尾灯 | 车尾也是红色圆灯 | 位置过滤（在画面下半部） |
| 绿色广告牌 | 大面积绿色矩形 | 面积上限 + 圆形度过滤 |
| 摄像头抖动 | 轮廓断裂 | 闭运算连接 |

### 阶段二：HSV 颜色空间

RGB 不适合颜色分割——同一个"红色"在不同光照下 RGB 值变化极大。HSV 把色调 (Hue) 和亮度 (Value) 分离，设阈值更直观。

红色的特殊处理：HSV 的 H 是环形（0-180），红色在 0° 附近跨越分界线。需要两段阈值 `[0,10]` 和 `[160,180]` 合并。

调参过程：一开始 S 下限设 100，结果白色墙面、灰色天空全部被当成红色——因为它们的 S 值很低。提高到 150 后大幅减少误检。

### 阶段三：形态学 + 几何过滤

颜色掩码出来后有大量噪点（几个像素的小斑点）。开运算（先腐蚀再膨胀）能去噪。闭运算（先膨胀再腐蚀）能填充灯内的暗区。

几何过滤是区分"红绿灯"和"看起来像红绿灯的东西"的关键：
- **面积**：红绿灯在图像中通常是 20-5000 像素
- **圆形度**：红绿灯是圆的（4πA/P² → 1.0），广告牌是方的（→ 0.785）
- **位置**：尾灯在画面底部

## 踩坑记录

### 坑 1：cv2.imread 中文路径（又一次！）

**现象**：40 张图全部 `can't open/read file`。

**原因**：和 C1 一样，`cv2.imread()` 不支持中文路径。项目路径含"智泽实验室招新"。

**解决**：
```python
# 用 np.fromfile + cv2.imdecode 替代
img = cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)

# 保存同理: imencode + 二进制写
success, buf = cv2.imencode('.jpg', img)
with open(path, 'wb') as f:
    f.write(buf.tobytes())
```

### 坑 2：红色 HSV 范围跨越 0°

**现象**：红色交通灯只检测到一半——有些红灯能检测到，有些检测不到。

**原因**：HSV 中 H 是环形，红色在 0° 和 180° 两端。只设一段范围（如 `[0, 10]`）会漏掉偏紫的红。

**解决**：两段范围取并集：
```python
RED_RANGE_1 = ((0, 150, 80), (10, 255, 255))
RED_RANGE_2 = ((160, 150, 80), (180, 255, 255))
mask = mask1 | mask2
```

### 坑 3：饱和度阈值调参与阳光反光

**现象**：白天场景中大量白色墙面、灰色天空被误检为红灯。

**原因**：这些区域的 H 值偏红（暖色调），但饱和度 S 很低。HSV 的红色范围只看 H 的话，低饱和度的白色也算"红"。

**解决**：S 下限从 100 提高到 150。真正的红绿灯饱和度很高（>150），白色/灰色物体 S 很低（<50）。

### 坑 4：传统 CV 的固有限制

**认识**：调了很久参数，发现传统方法对以下场景仍然吃力：
- 红绿灯在画面中非常小（< 20px）——面积下限与检测能力的 tradeoff
- 红色尾灯和红绿灯同时出现且都在画面中部——位置启发式失效
- 绿色交通灯和绿色树叶混在一起——颜色完全重叠

题目要求的"强鲁棒性"在纯传统 CV 方法下是有上限的。工业界实际产品（如自动驾驶）几乎全部使用深度学习。但作为学习练习，把 HSV + 形态学 + 几何过滤这条 pipeline 走通，对理解计算机视觉底层原理很有价值。

### 坑 5：绿色过检（GREEN 占了 28/40）

**现象**：初版检测器在 40 张图上 GREEN 占了 28 张，明显过检。

**原因**：两层叠加——
1. **绿色 HSV 范围太宽**：`H∈[45,85]` 跨度 40°，把树叶、草地、黄绿反光（H≈45-60）都当成绿灯。
2. **置信度没考虑颜色强度**：置信度只用 `面积×圆形度×位置`，一个又大又暗的绿色背景斑块能赢过又小又亮的真实红灯。

**解决**：
1. 绿色 H 下限 45→60（只保留纯正绿），S/V 下限相应提高。
2. 置信度加入 **颜色强度** `mean(S×V)/255²`——点亮的灯是高饱和+高亮度，反光/暗淡背景强度低。
3. 状态判定从"每色平均置信度"改为"取单灯最强候选"——避免噪声斑块平均后压过真实亮灯。

修完后 GREEN 从 28 降到 5，红黄分布更均衡。

### 坑 6：干扰数据集不能只写策略，要真生成图
